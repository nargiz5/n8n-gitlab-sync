# n8n → GitLab Workflow Sync

Automatically track n8n workflows in GitLab as version-controlled files — with commits, diffs, and AI-generated changelogs — without needing n8n's paid version control feature.

## What This Does

n8n has built-in workflow history and version restore, but full Git-based version control is an Enterprise-only feature. This workflow is a lightweight alternative: it runs on a schedule, detects which workflows actually changed, and pushes only real changes to GitLab as commits — with a human-readable changelog entry generated by AI for each one.

- Mirrors your n8n folder structure into matching GitLab groups/subgroups
- Ignores noise (node positions, internal version counters) and only commits real structural changes
- Auto-creates GitLab projects for new workflows
- Writes an AI-generated `CHANGELOG.md` entry for every real change
- Runs on a schedule (default: daily) and supports manual triggering

## How It Works

```
Schedule Trigger
     │
     ▼
Set GitLab Config (URL, group path/ID, token, root folder ID)
     │
     ▼
Read workflow tree from n8n's Postgres DB (via SSH)
     │
     ▼
For each workflow:
  ├─ Does a matching GitLab project exist?
  │    No  → create project, seed CHANGELOG.md
  │    Yes → continue
  ├─ Fetch current file from GitLab
  ├─ Diff against n8n's current version (noise-filtered)
  ├─ No real change → skip
  └─ Real change →
        ├─ Commit updated JSON to GitLab
        └─ Send diff to AI Agent → append entry to CHANGELOG.md
```

### Why SSH instead of the REST API

n8n's REST API doesn't expose folder structure on the free tier — there's no endpoint that tells you which folder a given workflow lives in. Folders are stored in n8n's Postgres database as a self-referencing table (each folder row points to its parent), so this workflow connects over SSH and runs a recursive query to reconstruct the full path for every workflow:

```sql
WITH RECURSIVE folder_tree AS (
  SELECT id, name, "parentFolderId", name::text AS folder_path
  FROM folder
  WHERE id = '{your_root_folder_id}'

  UNION ALL

  SELECT f.id, f.name, f."parentFolderId", ft.folder_path || '/' || f.name
  FROM folder f
  JOIN folder_tree ft ON f."parentFolderId" = ft.id
)
SELECT COALESCE(
  json_agg(
    json_build_object(
      'workflow_id', w.id,
      'workflow_name', w.name,
      'folder_path', ft.folder_path
    )
    ORDER BY ft.folder_path, w.name
  ),
  '[]'::json
)
FROM workflow_entity w
JOIN folder_tree ft ON w."parentFolderId" = ft.id
```

That `folder_path` (e.g. `prod/Marketing/Email-Sync`) is what the workflow later uses to build the matching group/subgroup path in GitLab.

### Why diffing needs to filter noise

n8n rewrites fields like node `position`, internal `versionCounter`, and credential IDs on almost every save — even when nothing meaningful actually changed. A naive JSON diff would treat every autosave as a "change" and flood GitLab with empty commits. The diff step strips these fields out first and only flags:
- Nodes added or removed
- Parameters changed
- Connections added or removed

## Prerequisites

- An n8n instance (self-hosted, with database access)
- A GitLab instance with a personal/project access token that has API + repository write scopes
- SSH access to the server running n8n's Postgres database
- An [OpenRouter](https://openrouter.ai) API key (or swap in any other LLM provider node)

## Setup

1. **Import the workflow.** Download [`Gitlab-n8n-synchronization-prod.json`](./Gitlab-n8n-synchronization-prod.json) and import it into your n8n instance.

2. **Reconnect credentials** in n8n. Every node's credential reference was stripped when this was published, so each `HTTP Request`, `SSH`, and `OpenRouter` node will show as unlinked after import — open each one and pick (or create) your own:

   | Credential type | Used by | Used for |
   |---|---|---|
   | HTTP Header Auth (`PRIVATE-TOKEN: <your GitLab token>`) | All GitLab `HTTP Request` nodes | Creating/reading/writing GitLab projects and files |
   | HTTP Header Auth | `GET workflow by ID` | Authenticating against your own n8n instance's REST API |
   | SSH Private Key | `n8n_backup.sh` | Connecting to the Postgres host to read the folder tree |
   | OpenRouter API | Both `OpenRouter Chat Model` nodes | Generating changelog entries |

3. **Fill in the `Set GitLab Config` node.** This is the first node after the trigger, and it's the single place all the GitLab/n8n config values live — nothing else in the workflow should need editing besides this node and the credentials above.

   | Field | Example | Notes |
   |---|---|---|
   | `GITLAB_URL` | `https://gitlab.example.com` | Your GitLab instance base URL |
   | `GITLAB_ROOT_FULL_PATH` | `yourgroup/n8n-backups` | The GitLab group path workflows will sync into |
   | `GITLAB_ROOT_GROUP_ID` | `123` | The numeric ID of that root GitLab group |
   | `N8N_ROOT_FOLDER_ID` | `abc123XYZ` | The n8n folder ID to track — find it in n8n's UI URL when viewing the folder, or by querying the `folder` table directly |
   | `GITLAB_PRIVATE_TOKEN` | `glpat-xxxxxxxx` | A GitLab access token with API + write_repository scope, used by the `Resolve GitLab subgroup path` code node |

   > ⚠️ These values are stored as plain text inside the node, which means they end up in the exported JSON — unlike the credentials above, which n8n encrypts and keeps out of exports. Fill this node in on your own instance, but **never export/commit/share this workflow with real values still in it.** If you plan to keep a copy of this workflow in a public repo, keep it with placeholder values and fill in the real ones only after importing.

4. **Adjust the schedule.** The `Schedule Trigger` node defaults to once daily; change the interval to whatever cadence fits your workflow volume. Very frequent runs (e.g. every few minutes) tend to catch workflows mid-edit and produce noisier history — daily or hourly is usually a better fit than real-time.

5. **Activate the workflow.** It will run on schedule from then on, and can also be triggered manually from the n8n canvas.

## Example Output

A synced workflow appears in GitLab as a `.json` file plus a `CHANGELOG.md`, with entries like:

```markdown
## 2026-08-15
- Updated the fetch endpoint to point to the new API version.
- Removed an unused error-handling branch after the retry node.
```

## Limitations

- The folder-tree query is written against n8n's current Postgres schema; if that schema changes in a future n8n version, the query may need updating.
